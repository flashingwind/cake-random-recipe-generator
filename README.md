# ケーキランダムレシピジェネレーター

パウンド・スポンジ・シフォンなどのケーキのレシピは、パラメータ空間では連続しているのではないか、という仮説の実験道具です。

## 使い方

`index.html` をブラウザで開くだけで動きます（静的サイト）。GitHub Pages で公開する場合は、このリポジトリの Settings → Pages で main ブランチを選んでください。

- **ランダム生成**：既存のケーキ（アンカー）を2つ選び、配合をランダムに補間します
- **手動指定**：スライダーでパラメータを動かすと、成立判定とレシピが連動します
- **成立判定**：膨らみ・水分・乳化・砂糖などの観点から、理由つきで目安を出します
- **パラメータ空間プロット**：立て方ごとにグラフを分け、公開レシピを使った重み付きk-NNの分類結果で領域を塗り分けます

## 設計メモ

- パラメータはすべて「小麦粉100gあたり」で表す（ベーカーズパーセント）
- 油脂は **純脂肪のグラム数** で数える。バターは重量×0.83、水分を含む素材としては別枠で数える
- グラフの横軸は二重目盛り：下が純脂肪、上はバター換算（計算尺の発想）
- 非連続な変数（立て方：クリーミング／共立て／別立て）は軸に入れず、グラフ自体を分ける
- アンカーはネットの定番レシピから換算した概算値。増やすほど領域の解像度が上がる
- ※ ジェノワーズとカステラの卵量は、ネットの定番レシピの範囲（ジェノワーズ：粉100あたり卵167〜200g、カステラ：同200〜260g）に合わせて調整済み（2026-11-09確認）

## 今後の課題

- アンカー（既存レシピ）を増やして領域塗り分けの解像度を上げる
- 成立判定のルールの精度を、実際に焼いた結果で検証する
- 焼き上がりの記録（写真・感想）をパラメータと紐づけて残す

## 領域グリッドと実データの食い違い

`node scripts/train-classifier.cjs` で公開データを読み込み、重複（出典URL・カテゴリ・配合が同じもの）を除いて `data/classifier-model.js` と評価結果を生成します。現在は77件中76件が重複しない実レシピです。カテゴリは各8〜15件の試作段階です。

背景は `region-grid.js` で実レシピだけを使って計算します。従来の固定断面SVMグリッドは保持していますが、画面表示には使いません。脂肪・卵・水分を実データの標準偏差で標準化し、水分を現在値に固定した断面を表示します。概算アンカーは支持範囲や分類には含めません。

- 色付き：近傍に実データがある。支持範囲内の近い5件までを距離の二乗の逆数で重み付けしてカテゴリを選ぶ。
- 2色の斜線：同じ立て方のグラフ内で、選ばれたカテゴリ以外にも近い実データがある。別の立て方との重なりでは斜線にしない。両カテゴリが支持範囲内にあり、第2カテゴリの最短距離が第1カテゴリの最短距離×1.5＋0.15以下の場合。
- グレー：支持範囲内に実データがない。
- 白抜き：支持されるカテゴリがそのグラフの立て方と異なる。

支持半径はカテゴリ内での最近傍距離の90パーセンタイルを使い、0.35〜1.25に制限しています。これは疎なデータから遠くまで塗り広げないための暫定的な目安で、校正された確率や焼成の成立判定ではありません。境界・斜線のセルは24ピクセルから約3ピクセルまで適応的に細分化します。

カテゴリの基本色は維持しています。家庭用／標準的の濃淡は、予測カテゴリ内で脂肪・卵が最も近いアンカーの区分に従います。「（家庭用）」付きは薄く、それ以外は濃く表示します。重心は表示しません。全76件の実レシピを点として投影しますが、水分が異なれば別カテゴリやグレーの背景上にも点が現れます。クリックすると現在の3特徴に近い実レシピと出典が見られます。

`node scripts/analyze-regions.cjs` で、同じ出典URLのデータを除いて近傍分類し直した要確認点を `data/region-review.json` に出力します。他カテゴリへ入る点と、異なるラベルが近接する点を区別しています。誤ラベルと断定したり、自動修正したりはしません。原文の材料・換算・立て方・カテゴリ名を確認し、その周辺の新規実レシピを収集するための優先候補です。計算した配合を新しい実データとして追加することはありません。

検証：`node --test tests/region-grid.test.cjs`。従来のk-NN評価（公開データのみ・出典ホスト単位の交差検証で67/76件正解）とSVM評価は比較用に残していますが、支持範囲による棄却と食い違い表示の精度を保証する数値ではありません。

## データ収集の継続

段階的に合計約1,000件を目指し、中心付近に加えて要確認点の周辺を優先します。`data/collection-plan.json` の各30件は最初の段階の目標です。`python3 scripts/collect-recipes.py` は候補ページを `/workspace/recipe-source-cache` に保存します。原文・換算・立て方・重複を確認して `data/recipes.json` に追加し、学習・分析コマンドを再実行してください。現環境ではレシピサイトへの通信が403で拒否されており、必要なドメインの許可設定案を保存しています。

分類と背景描画には脂肪・卵・水分の3項目だけを使います。砂糖とBPのデータやスライダーは、レシピ生成と成立判定のために保持しています。

## 3D全体図と2D断面図

基本表示は脂肪・卵・水分の3D全体図です。全76件の実レシピとアンカーを水分で絞り込まず表示します。ドラッグ・矢印キーで回転、ボタン・プラス／マイナスで拡大縮小、Homeキーまたは「向きを戻す」で初期視点に戻ります。実レシピの点をクリックすると配合と出典を表示します。依存ライブラリや外部CDNは不要です。

上部の水分スライダーは1個だけで、生成レシピを調整します。折りたたみの2D断面図を開いたときは同じ水分値を断面位置に使います。3Dは点の分布と半透明の領域を重ねます。家庭用／標準的の濃淡と同じ立て方での近接を示す斜線を使い、データ不足は透明にします。チェックボックスで領域だけを非表示にできます。領域は18×24×24の3次元格子の中心で実データの支持範囲を判定し、同じ区分内の内部面を除いた表面を描画する近似です。格子より細かい形状は表現しません。水分スライダーは3Dの支持範囲を変えません。
